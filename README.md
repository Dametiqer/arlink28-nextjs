# ARLink28 — Next.js Source (Reconstructed)

## What this is

The zip you provided (`arlink28 new/`) wasn't Next.js *source code* — it was the
**static-exported build output** of a Next.js App Router site (you can tell from
the `_next/static/chunks/*.js` bundles, the build manifest, etc.). There was no
`app/`, `pages/`, `.tsx`, or `package.json` in it — just fully rendered HTML.

This project is a **reverse-engineered, working Next.js 14 (App Router,
TypeScript) rebuild** of that site, generated by parsing the rendered HTML of
every page into a real component tree.

## How it was rebuilt

- Every page's `<header>`, `<footer>`, and `<main>` content was extracted from
  the static HTML and converted to JSX with a custom tree-based HTML→JSX
  converter (not regex string-replacement), so tag nesting is guaranteed to
  match the original DOM.
- The shared `<header>`/nav and `<footer>` became `components/Header.tsx` and
  `components/Footer.tsx`, reused by the root layout (`app/layout.tsx`) —
  matching the way the original site clearly shared them across pages.
- All internal links (`href="/about.html"`, etc.) were rewritten to
  extension-less Next.js routes (`/about`) using `next/link`.
- All CSS chunks from `_next/static/chunks/*.css` were merged into
  `app/globals.css`, keeping the real design tokens (`:root` custom
  properties), the Google Font import (Outfit), and all page-specific styles.
- Font Awesome icons are loaded the same way the original did: a CDN
  stylesheet link in `app/layout.tsx`.
- All 147MB of images/video in `images/` were copied as-is into `public/images`.

## Interactivity that had to be rebuilt (not just copied)

The static export only contains rendered *output* — the original client-side
JavaScript that powered interactions wasn't recoverable (it lived in minified,
bundled `.js` chunks with no source maps). These behaviors were re-implemented
from scratch to match what the CSS/markup clearly expected:

- **Mobile menu toggle** — `components/Header.tsx` (`useState`).
- **Scroll-reveal animations** (`.reveal`, `.reveal-left`, `.reveal-right`,
  `.reveal-scale` classes already existed in the CSS, toggling a `.visible`
  class) — reimplemented with `IntersectionObserver` in
  `components/ClientEffects.tsx`.
- **Homepage booking widget tabs** (Flight / Hotel / Holiday / Visa) —
  `components/BookingWidget.tsx`, using simple DOM class/style toggling on
  click, matching the panel `id`s already present in the markup.
- **Newsletter/contact form submission** — since there's no backend in the
  original export either, submitting currently just resets the form
  (`ClientEffects.tsx`). Wire this up to a real API route or provider
  (e.g. Formspree, Mailchimp, your own `/api` route) when you're ready.

## ⚠️ One page group could not be recovered: `/book/*`

In the original build, `/book/flight`, `/book/hotel`, `/book/holiday`, and
`/book/visa` were **client-only components** — Next.js's static export
literally only shipped a `<div>Loading...</div>` placeholder for them
(`BAILOUT_TO_CLIENT_SIDE_RENDERING`), meaning their real markup only ever
existed in the browser after JS hydration, and isn't present anywhere in the
zip you gave me.

To keep these routes functional, `app/book/{flight,hotel,holiday,visa}/page.tsx`
each render the **same booking widget recovered from the homepage** (which
does have full markup — including the complete African airport dropdown
lists), pre-selecting the matching tab. Treat these four pages as a
reasonable placeholder, not a byte-for-byte reconstruction — you'll likely
want to redesign them as dedicated full-page booking flows.

## Getting started

This sandbox has no network access, so **this project has not been
`npm install`'d or built/tested** — do that first:

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

To build for production:

```bash
npm run build
npm start
```

## Suggested next steps

- Swap `<img>` tags for `next/image` where you want automatic optimization
  (currently `next.config.mjs` sets `images.unoptimized: true` so plain
  `<img>` tags behave exactly like the original static export).
- Wire the newsletter/contact forms up to a real backend.
- Consider loading the "Outfit" Google Font via `next/font/google` instead of
  the CSS `@import` in `globals.css`, for better performance.
- Rebuild the four `/book/*` pages as proper dedicated flows once you decide
  what the booking backend/API should look like.
